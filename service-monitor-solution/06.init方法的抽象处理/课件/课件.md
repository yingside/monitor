## init方法的抽象处理

监控的工作比较复杂，并且种类繁杂，需要针对不同的内容进行监控，并且可能还有不同的上报策略。所以针对不同的业务内容，需要有一种比较灵活的方式进行接入。其实简单来说，就是针对上层进行抽象，底层进行实现。所以我们使用面向对象的方式来处理这个问题比较简单。

有了这样的方案之后，可以抽象出几点重要内容

1. 监控monitor实例对象初始化
2. 插件的注册和消费
3. 上报协议定义与初始化

### 伪代码来描述

```typescript
// 监控实例对象
const 监控实例 = new 监控({
  dsn: options.dsn,
  // 插件注册和消费
  integrations: options.integrations
})

// 定义上报方式
// 不同的平台有不同的上报逻辑BrowserTransport，应该是一个子类
// 具体的上报方式 在BrowserTransport完成，这里只是负责实现
const transport = new BrowserTransport(options.dsn)
// 传入上报方式，完成初始化
监控实例.init(transport)

// 错误采集
new Errors(transport).init()

// 性能采集
new Metrics(transport).init()
```

### 代码逻辑处理：

```typescript
interface InitOptions {
  dsn: string;
  integrations?: any[];
}

class Monitor {
  dsn: string;
  integrations: any[];
  constructor(options: InitOptions) {
    this.dsn = options.dsn;
    this.integrations = options.integrations || [];
  }

  init(transport: Transport) {
    // 在这个方法中，只需要关注Transport的send方法即可
    // 无论你用的是哪种上报方式，最终都会调用这个方法
    // transport.send({});
  }
}
// BrowserTransport只是上报的其中一个

type Transport = BrowserTransport; /*  | NodeTransport | ImageTransport | XHRTransport | FetchTransport; */

// BrowserTransport 类用于处理浏览器环境中的数据上报
// 例如使用 fetch、XMLHttpRequest、Image 对象或 sendBeacon 方法
// 在这里抽象出上报逻辑，使用的时候无需关心具体的上报方式
class BrowserTransport {
  constructor(private dsn: string) {}

  send(data: Record<string, unknown>) {
    // 1. fetch
    // fetch()
    // 2. xhr
    // new XMLHttpRequest()
    // 3. img
    // const img = new Image(); img.src = xxx;
    // 4. sendBeacon
    // navigator.sendBeacon(xxx);
    console.log("浏览器上报", data);
  }
}

export const init = (options: InitOptions) => {
  const monitor = new Monitor(options);

  // 定义上报逻辑
  // transport会调用send方法来上报数据
  // 但是我们这里不需要关注，只是进行抽象，需要具体哪些对象来进行即可
  const transport = new BrowserTransport(options.dsn);

  monitor.init(transport);

  // 错误采集
  // new Errors(transport).init();
  // 性能采集
  // new Metrics(transport).init();

  return monitor;
};

```
