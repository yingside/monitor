## 项目概述

打造一个完整的企业级前端监控解决方案，包括SDK(原生JS，Vue，React)、数据服务后端(Nest.js)、数据看板(可视化平台)。项目的核心目标是帮助开发团队对应用进行实时性能监控和异常捕获，支持快速响应和修复问题，提高产品稳定性和用户体验。

由于之前课程已经将SDK的重要内容比较详细的给大家梳理了一次，本次项目的重心主要放在企业级项目处理、架构设计、后端处理和前端可视化平台的处理之上。

## 基础业务需求

- **性能监控**
- **异常监控**
- **数据可视化与分析**：收集的数据不仅需要展示给开发者，最好能通过一目了然的图表等形式让团队成员轻松的理解数据趋势。而且需要支持实时数据更新、过滤和事件追踪等功能。可视化平台需要具有数据删选和分组的功能，这样可以让团队按照项目、页面、时间等维度分析性能和异常问题，从而做出更具数据驱动的决策。

## 技术需求

- **多框架SDK支持**：参照Sentry设计，SDK应提供对多种前端框架的支持，比如原生JS，React，Vue等等。这样方便集成到不同的项目。SDK在架构上应该支持插件化扩展。性能上应该实现高效的数据采集
- **数据服务后端**：后端使用Nest.js搭建框架，数据服务需要能高效的接收大量前端数据上报请求并且能稳定运行。同时，需要具备数据预处理的功能，将不同类型的数据进行过滤、分类和清洗，并支持按需存储，以便在可视化展示时减少数据冗余
- **数据可视化平台**：基于React和Nest.js构建数据可视化平台，应该支持丰富的数据展示功能，实时数据流，各种数据图表等等，前端需实现用户友好的交互，支持不同维度数据的分析和过滤。

## 技术选项

### 基本架构

- 主要参考Sentry的架构设计模式，项目整体采用pnpm monorepo管理，核心包实现基本功能，各个适配包负责集成不同的框架
- 使用TypeScript提供类型支持
- SDK适配不同的框架，实现监控采集数据，主要包括性能指标和异常数据

### 监控内容

- 性能监控，通过webvital和Performance API收集web性能指标
- 错误异常监控
- 埋点上报，主要通过HTTP协议上报数据到后端，通过插件化设计方便扩展更多的监控和上报逻辑

### 数据采集后端服务

- 后端框架：使用Nest.js构建后端服务
- 消息队列：使用kafka实现消息队列，定义不同的topics以及oartition提升服务稳定性与性能
- 数据处理与存储：设计对应的数据处理服务，进行数据清洗、聚合等操作。集成Clickhouse列式数据库进行数据存储，可以更方便快速的进行数据查询与分析
- 通信协议：数据采集通过HTTP接口接收SDK上报的数据

### 数据看板

可视化平台采用React + tailwind + shadcn/ui 进行数据展示

## 工程基础结构

```
.
├── apps														// 业务应用文件夹
│   ├── backend											// 后端服务文件夹
│   └── frontend										// 前端服务文件夹
├── demos														// 示例代码文件夹
│   ├── react
│   ├── vanilla
│   └── vue
├── package.json
├── packages												// SDK相关封装
│   ├── browser											// 浏览器监控核心包
│   ├── browser-utils								// 浏览器工具函数包
│   ├── core												// SDK核心包
│   ├── react												// React框架适配包
│   ├── utils												// 通用工具函数包
│   └── vue													// Vue框架适配包
├── pnpm-workspace.yaml							// pnpm monorepo 工作空间管理配置文件
└── README.md												// README说明文件
```

> **PS**:上面的目录结构可以使用`linux`命令`tree`打印，更方便的可以使用命令
>
> `tree -I "node_modules" > README.md`
>
> 忽略`node_modules`文件夹，并将文件夹内容输出到`README.md`文件

**pnpm-workspace.yaml**

```shell
packages:
  - 'packages/*'
  - 'apps/backend/*'
  - 'apps/frontend/*'
  - 'demos/*'
```
