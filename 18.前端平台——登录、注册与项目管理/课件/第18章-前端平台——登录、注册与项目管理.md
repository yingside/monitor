## 二、为什么需要 TanStack Query？

> 📖 **术语：服务端状态（Server State）**
> 白话来说：放在后端服务器上、需要通过 HTTP 请求才能拿到的数据。
> 对比：前端本地的 UI 状态（弹窗开不开、Tab 选哪个）叫**客户端状态**。

### 2.1 不用 TanStack Query 会怎样？

假设用传统的 `useState` + `useEffect` + `axios`：

```typescript
// ❌ 典型问题代码
function ProjectsPage() {
  const [projects, setProjects] = useState([])
  const [isLoading, setIsLoading] = useState(false)
  const [error, setError] = useState(null)

  useEffect(() => {
    setIsLoading(true)
    axios.get('/projects')
      .then(res => setProjects(res.data.data))
      .catch(err => setError(err))
      .finally(() => setIsLoading(false))
  }, [])

  // 问题：
  // 1. 每次进入页面都重新请求，即使数据一分钟内没变
  // 2. 创建项目后需要手动再 fetch 一次列表
  // 3. 多个组件同时需要 projects 数据？每个都各自请求一次
  // 4. 离开页面再回来：loading 闪烁
}
```

### 2.2 TanStack Query 解决了什么？

> 🏗️ **架构思考**
> TanStack Query 的核心价值：**把"与后端同步数据"这件事从业务逻辑中抽出来**，变成可复用的基础设施层。
>
> - 职责边界：组件只负责"展示数据"，缓存/失效/重请求 由 TanStack Query 全权接管
> - 可替换方案：SWR（更轻量，API 更简单）、RTK Query（Redux 生态）

| 问题 | TanStack Query 方案 |
|---|---|
| 重复请求 | 同一 QueryKey → 缓存 → `staleTime` 内不重新请求 |
| 写操作后刷新 | `invalidateQueries` 精准清除，自动重新请求 |
| 多组件共享 | 同一 QueryKey 共用一份缓存，只发一次请求 |
| 加载/错误状态 | `isPending` / `isError` / `error` 自动管理 |

## 三、安装与配置

### 3.1 安装依赖

```bash
pnpm --filter @monitor/frontend add @tanstack/react-query
```

### 3.2 在 `main.tsx` 初始化 QueryClientProvider

> 📖 **术语：QueryClient**
> 白话：TanStack Query 的"大脑"——管理所有请求的缓存、状态和配置。
> 整个应用只需要一个，通过 Provider 注入到所有组件。

```typescript
// src/main.tsx
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      retry: 1,                    // 失败重试 1 次（默认 3 次）
      refetchOnWindowFocus: false, // 切换窗口不自动重请求
    },
  },
})

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </StrictMode>,
)
```

> 📌 **为什么 `refetchOnWindowFocus: false`？**
> TanStack Query 默认在浏览器 Tab 重新获焦时重新请求（确保数据最新）。
> 对监控平台来说，这会干扰开发调试（频繁切换 Tab 时不断 loading）。
> 生产应用可以开启。

## 四、服务层设计：解包 ApiResponse

所有对 monitor-server 的请求都返回统一格式：

```json
{ "code": 0, "data": {...}, "message": "ok" }
```

services 层的职责是：**发请求 + 解包，只返回 `data` 字段**。

```
components/pages
    ↓ 调用 hooks（useQuery/useMutation）
hooks（处理缓存、store 副作用）
    ↓ 调用 services
services（Axios + 解包 ApiResponse<T>）
    ↓
request.ts（JWT 注入 + 401 处理）
    ↓
monitor-server API
```

### 4.1 创建 `src/services/auth.service.ts`

```typescript
import request from '@/utils/request'
import type { ApiResponse } from '@/types/api'
import type { AuthResponse, LoginDto, RegisterDto, User } from '@/types/auth'

export async function loginApi(dto: LoginDto): Promise<AuthResponse> {
  const { data } = await request.post<ApiResponse<AuthResponse>>('/auth/login', dto)
  return data.data
}

export async function registerApi(dto: RegisterDto): Promise<AuthResponse> {
  const { data } = await request.post<ApiResponse<AuthResponse>>('/auth/register', dto)
  return data.data
}

export async function getProfileApi(): Promise<User> {
  const { data } = await request.get<ApiResponse<User>>('/auth/profile')
  return data.data
}
```

### 4.2 创建 `src/services/project.service.ts`

```typescript
import request from '@/utils/request'
import type { ApiResponse } from '@/types/api'
import type { Project, CreateProjectDto, UpdateProjectDto } from '@/types/project'

export async function getProjectsApi(): Promise<Project[]> {
  const { data } = await request.get<ApiResponse<Project[]>>('/projects')
  return data.data
}

export async function createProjectApi(dto: CreateProjectDto): Promise<Project> {
  const { data } = await request.post<ApiResponse<Project>>('/projects', dto)
  return data.data
}

export async function updateProjectApi(id: string, dto: UpdateProjectDto): Promise<Project> {
  const { data } = await request.patch<ApiResponse<Project>>(`/projects/${id}`, dto)
  return data.data
}

export async function deleteProjectApi(id: string): Promise<void> {
  await request.delete(`/projects/${id}`)
}
```

## 五、认证 Hooks（useMutation）

> 📖 **术语：useMutation**
> 白话：专门处理"会改变后端数据的操作"（登录/注册/增删改），对应 HTTP 的 POST/PATCH/DELETE。
> 对比：`useQuery` 专门处理"查数据"（GET 请求）。

### 5.1 创建 `src/hooks/useAuth.ts`

```typescript
import { useMutation } from '@tanstack/react-query'
import { useNavigate } from 'react-router-dom'
import { useAuthStore } from '@/stores/auth.store'
import { loginApi, registerApi } from '@/services/auth.service'

export function useLogin() {
  const { setAuth } = useAuthStore()
  const navigate = useNavigate()

  return useMutation({
    mutationFn: (dto: LoginDto) => loginApi(dto),
    onSuccess: (data) => {
      setAuth(data.token, data.user)
      navigate('/projects', { replace: true })
    },
  })
}

export function useRegister() {
  const { setAuth } = useAuthStore()
  const navigate = useNavigate()

  return useMutation({
    mutationFn: (dto: RegisterDto) => registerApi(dto),
    onSuccess: (data) => {
      setAuth(data.token, data.user)      // 注册即登录
      navigate('/projects', { replace: true })
    },
  })
}
```

> 🏗️ **架构思考**
> 为什么 `onSuccess` 在 hook 里，而不是在组件里？
>
> - 登录成功后"写 store + 跳路由"是**固定的业务规则**，不应该散落在各个使用登录的地方
> - 把副作用放在 hook 里，组件只需要调用 `mutate(dto)`，不关心成功后发生什么
> - 备选方案：在 `useMutation` 的 `onSuccess` 组件侧回调里写，更灵活但更分散

## 六、项目 Hooks（useQuery + useMutation）

### 6.1 Query Key 统一管理

> 📖 **术语：Query Key（查询键）**
> 白话：TanStack Query 用一个数组作为"缓存地址"，把数据存在这个地址下。
> 清除缓存时，只要 key 一样就能精准命中。

```typescript
// src/hooks/useProjects.ts
export const QUERY_KEYS = {
  projects: ['projects'] as const,
  project: (id: string) => ['projects', id] as const,
}
```

### 6.2 查询 Hook（useQuery）

```typescript
export function useProjects() {
  return useQuery({
    queryKey: QUERY_KEYS.projects,
    queryFn: getProjectsApi,
    staleTime: 1000 * 60 * 5,   // 5 分钟内不重新请求
  })
}
```

**`staleTime` 的含义：**

```
请求完成 → 数据"新鲜"（fresh）
   ↓ 5 分钟过后
数据"陈旧"（stale）→ 下次访问时重新请求
```

### 6.3 写操作 Hook + 缓存失效

```typescript
export function useCreateProject() {
  const queryClient = useQueryClient()

  return useMutation({
    mutationFn: (dto: CreateProjectDto) => createProjectApi(dto),
    onSuccess: () => {
      // 使项目列表缓存失效 → TanStack Query 自动重新请求列表
      queryClient.invalidateQueries({ queryKey: QUERY_KEYS.projects })
    },
  })
}
```

> 🏗️ **架构思考**
> `invalidateQueries` 是 TanStack Query 的核心模式：**写操作成功后，主动宣布相关缓存"过期"**。
>
> 对比手动刷新：
> - 传统做法：`setProjects([...projects, newProject])`（乐观更新，但需要自己维护状态）
> - TanStack 做法：`invalidateQueries` → 自动重新 fetch，永远展示服务器真实状态
> - 适用场景判断：数据量小、不需要"立即看到操作结果"的场景用 invalidate 更简单可靠

## 七、登录页接入真实 API

### 7.1 关键改动点

```typescript
// src/pages/auth/LoginPage.tsx

// Before（第 17 章）
const [isLoading] = useState(false)
const handleSubmit = (e) => {
  e.preventDefault()
  console.log('Login:', { email, password }) // 占位
}

// After（第 18 章）
const { mutate: login, isPending, error } = useLogin()

  e.preventDefault()

```

**错误提示从 axios error 提取：**

```typescript
const errorMessage = (() => {
  if (!error) return null
  const axiosError = error as { response?: { data?: { message?: string } } }
  return axiosError.response?.data?.message ?? '登录失败，请检查邮箱或密码'
})()
```

> 📌 **为什么不直接写 `error.message`？**
> axios 的 `error.message` 是 HTTP 层面的报错（如"Request failed with status code 401"）。
> 我们需要的是后端返回的业务错误（如"邮箱或密码不正确"），存在 `error.response.data.message`。

## 十、项目管理弹窗设计

### 10.1 ProjectFormDialog（新建/编辑双模式）

```
open + !project  → 新建模式
open + project   → 编辑模式（appId 只读）
```

关键实现点：

```typescript
// 1. 用 useEffect 在 open / project 变化时重置表单
useEffect(() => {
  if (project) {
    setAppId(project.appId)
    setName(project.name)
    // ...
  } else {
    setAppId('')
    setName('')
    // ...
  }
}, [project, open])

// 2. 提交时根据 isEditMode 调用不同的 mutation
const handleSubmit = (e: React.FormEvent) => {
  e.preventDefault()
  if (isEditMode && project) {
    updateProject.mutate(
      { id: project.id, dto: { name, description, platform } },
      { onSuccess: () => onOpenChange(false) },   // 成功后关闭弹窗
    )
  } else {
    createProject.mutate(
      { appId, name, description, platform },
      { onSuccess: () => onOpenChange(false) },
    )
  }
}
```

> 🏗️ **架构思考**
> **为什么 `onSuccess` 写在 `mutate()` 的第二参数，而不是 hook 的 `onSuccess`？**
>
> - hook 里的 `onSuccess`：全局生效，每次调用都执行
> - `mutate()` 第二参数的 `onSuccess`：这次调用特有，适合"关闭弹窗"这种一次性 UI 操作
> - 规则：**通用副作用（缓存失效）放 hook，局部 UI 操作（关弹窗）放调用侧**

### 10.2 appId 的重要性

```
     SDK 初始化         数据上报            监控平台
   MonitorBrowser       DSN Server         ProjectsPage
   .init({ appId:  →   存入 Kafka  →   ClickHouse 查询
   'vue3-demo' })           ↓             WHERE appId = ?
                       Consumer写入
                       ClickHouse
```

**appId 是贯穿整条链路的唯一标识**，SDK 和监控平台必须使用完全相同的值。

## 十三、常见问题排查

| 现象 | 排查思路 |
|---|---|
| 登录报 401 | monitor-server 未启动，或 PostgreSQL 中没有该用户 |
| 登录报"邮箱或密码不正确" | 检查密码，或用 mock 账号 test@example.com / test123456 |
| 项目列表一直加载 | monitor-server 未启动（端口 3003） |
| 创建项目报"appId 已存在" | 该 appId 已被该用户创建过，换一个或删除旧的 |
| demos 数据不在监控平台出现 | appId 不一致、或 dsn-server / consumer-server 未启动 |
